# 019 – JWT tokens

## Goal

Replace per-request password checks with signed, short-lived access tokens: the login endpoint
issues a JWT, protected endpoints verify it without touching the database.

## Key concepts

### Structure

```
eyJhbGciOiJIUzI1NiJ9 . eyJzdWIiOiIwMTk5...In0 . 3q2-7wWm1k...
   header (base64url)      claims (base64url)       signature
```

- **header** – algorithm (`alg`) and type,
- **claims** – JSON payload; *signed, not encrypted* – anyone can read it (jwt.io), never put secrets there,
- **signature** – proves the token was issued by the key holder and not modified (integrity).

Registered claims (RFC 7519):

| Claim | Meaning | Here |
|-------|---------|------|
| `sub` | subject (who) | user id |
| `iss` | issuer | `room-booking-service` |
| `aud` | audience (for whom) | `room-booking-api` |
| `exp` | expiration (Unix seconds) | now + 15 min |
| `iat` | issued at | now |
| `nbf` | not before | – |
| `jti` | unique id | UUID (revocation lists) |

Private claims: `email`, `role`.

### Algorithms

| | Signing key | Verification key | Use |
|---|---|---|---|
| HS256 (HMAC) | shared secret | same secret | one service issues and verifies (this step) |
| RS256 / PS256 (RSA), ES256 (ECDSA), EdDSA | private key | public key | identity providers; many services verify without being able to issue (020) |

Pin the expected algorithm on verification (`Validation::new(Algorithm::HS256)`) – never trust
`alg` from the token (`alg: none`, RS/HS confusion attacks).
HS256 secret: random, ≥ 32 bytes, from env/secret store (`APP_AUTH__JWT_SECRET`).

### jsonwebtoken crate

```rust
// issue
let claims = Claims { sub: user.id, exp: (now + ttl).timestamp(), iss, aud, ... };
let token = encode(&Header::new(Algorithm::HS256), &claims, &EncodingKey::from_secret(secret))?;

// verify
let mut validation = Validation::new(Algorithm::HS256);
validation.set_issuer(&["room-booking-service"]);
validation.set_audience(&["room-booking-api"]);
validation.set_required_spec_claims(&["exp", "iss", "aud", "sub"]);
validation.leeway = 30;                                   // clock skew tolerance (s)
let claims = decode::<Claims>(&token, &DecodingKey::from_secret(secret), &validation)?.claims;
```

Version 10+ requires choosing a crypto backend feature: `rust_crypto` or `aws_lc_rs`.

### Flow

```
POST /auth/login {email, password}  ──▶ verify Argon2 hash ──▶ 200 {accessToken, tokenType:"Bearer", expiresIn:900}
GET /users/me
Authorization: Bearer eyJ...         ──▶ AuthUser extractor: verify signature, exp, iss, aud ──▶ handler
```

Errors (RFC 6750):

```http
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer realm="room-booking", error="invalid_token", error_description="token expired"
```

No header → `WWW-Authenticate: Bearer realm="room-booking"` (no `error`).

### Stateless trade-offs

| + | − |
|---|---|
| no DB lookup / session store per request | token valid until `exp` even after logout, password change, role change |
| scales horizontally, works across services | revocation needs extra state (denylist of `jti`, token version per user) |
| cheap verification (HMAC) | token size grows with claims |

Mitigations: short access-token lifetime (5–15 min) + **refresh tokens** (long-lived, stored
server-side, rotated on each use, revocable) to obtain new access tokens without re-entering the password.

### Where to keep tokens on the client

- SPA/browser: in memory; refresh token in an `HttpOnly; Secure; SameSite` cookie. `localStorage` is readable by any injected script (XSS).
- Mobile/CLI: platform secure storage.
- Never in URLs (logs, referrers, browser history).

## Try it

```bash
cp .env.example .env      # contains a development APP_AUTH__JWT_SECRET
cargo run
B=localhost:3000/api/v1
TOKEN=$(curl -s -X POST $B/auth/login -H 'content-type: application/json' \
  -d '{"email":"user@booking.local","password":"user-password-123"}' | jq -r .accessToken)
echo $TOKEN | cut -d. -f2 | base64 -d 2>/dev/null; echo     # claims are readable!
curl -H "Authorization: Bearer $TOKEN" $B/users/me
curl -i -H "Authorization: Bearer ${TOKEN%?}x" $B/users/me     # tampered -> 401 invalid_token
APP_AUTH__ACCESS_TOKEN_TTL_MINUTES=-1 cargo run                 # issued tokens are already expired
```
